# Функциональные требования к приложению

| Код  | Требование                                                                 | Комментарий                                                                 |
|------|----------------------------------------------------------------------------|-----------------------------------------------------------------------------|
| **Функциональные (Functionality)**                                         |                                                                             |
| F1   | Подача заявок на депозиты через сайт и интернет-банк                       | Сайт: анкета с ФИО и телефоном (для новых клиентов). Интернет-банк: выбор счета и суммы (для существующих клиентов) |
| F2   | Отображение актуальных и персонализированных ставок по депозитам           | Критично для принятия решения клиентом, обеспечивает конкурентное преимущество |
| F3   | Подтверждение операций через СМС-код и уведомления о статусе заявки        | Обязательно для безопасности операций. Уведомления включают подтверждение ставки и открытие депозита |
| F4   | Обработка заявок менеджерами бэк-офиса с подтверждением в АБС              | Менеджеры могут предлагать особые условия. Для заявок с сайта - прозвон клиента колл-центром |
| F5   | Автоматизированное управление ставками (замена Excel)                      | Централизованное управление продуктами, исключение рисков человеческого фактора и небезопасной передачи данных |
| F6   | Идентификация новых клиентов в отделении банка                             | Регуляторное требование банковского законодательства                       |
| **Удобство использования (Usability)**                                     |                                                                             |
| U1   | Интуитивно понятный и удобный интерфейс подачи заявки                      | Критично для привлечения молодой аудитории, снижает барьеры использования цифровых каналов |
| U2   | Соблюдение корпоративной системы дизайна и брендинга                       | Единообразие пользовательского опыта, привычные цвета и брендированные элементы |
| U3   | Отображение статуса заявки на открытие депозита                            | Информирование клиента о ходе операции, поскольку процесс открытия не быстрый |
| **Надёжность (Reliability)**                                               |                                                                             |
| R1   | Доступность 24/7 с уровнем 99,9%                                          | Банковские услуги должны быть доступны постоянно                          |
| R2   | Отказоустойчивость с переключением на резервный ЦОД                        | Критично для непрерывности банковского бизнеса. Резервный ЦОД имеется     |
| R3   | Изоляция нагрузки от АБС                                                   | Избежание прямого API взаимодействия с перегруженной АБС для исключения проблем с доступностью |
| R4   | Защита передаваемых данных механизмом шифрования                           | Обязательно для защиты персональных и финансовых данных, использование TLS/SSL |
| **Производительность (Performance)**                                       |                                                                             |
| P1   | Время отклика операций менее 1 секунды                                     | Пользователи ожидают мгновенной реакции. Требуется оптимизация загрузки справочных данных |
| P2   | Поддержка высокой нагрузки от большого количества заявок                   | Предотвращение деградации производительности при росте                    |
| P3   | Горизонтальное масштабирование интернет-банка                              | Распределение нагрузки между серверами и ЦОД для роста пользовательской базы |
| **Поддерживаемость (Supportability)**                                      |                                                                             |
| S1   | Использование существующих технологий банка                                | MS SQL, Oracle, Java, PL-SQL. Снижает затраты на обучение и поддержку    |
| S2   | Совместимость новых технологий с существующими платформами                 | Обеспечивает интеграцию без полной замены систем                          |
| S3   | Минимальные изменения в ядре интернет-банка                                | Снижает зависимость от внешних ресурсов и стоимость внедрения            |
| S4   | Разработка документации для расширения системы                             | Критично для масштабирования решения на другие продукты и продолжения цифровизации |
| S5   | Рассмотрение микросервисной архитектуры для новых модулей                  | Подготовка к будущему масштабированию и развитию, снижение связанности сервисов |
| **Ограничения (Restrictions)**                                             |                                                                             |
| +R1  | Защита персональных данных (ФИО, телефон)                                  | Требуется защищенный канал передачи, шифрование при хранении согласно законодательству |
| +R2  | Разделение доступа к данным по кредитам и депозитам в АБС                  | Требование безопасности данных                                            |
| +R3  | Использование Kafka для очередей сообщений в перспективе                   | Технологическая стратегия банка, но текущая версия интернет-банка несовместима |
| +R4  | АБС поддерживает только вертикальное масштабирование                       | Ограничение существующей архитектуры, база данных уже перегружена        |
| +R5  | Участие менеджеров бэк-офиса в MVP версии                                  | Переходное ограничение до полной автоматизации                            |
