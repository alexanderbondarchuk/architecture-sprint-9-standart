### **Решение**

**Архитектурная логика и обоснование решений:**

1. **Централизованное управление ставками** через сервис депозитов, который уже существует в архитектуре MVP
2. **Двухканальная интеграция**: REST API для внутреннего колл-центра и SFTP для партнерского
3. **Кэширование ставок** в отдельной БД для снижения нагрузки на АБС
4. **Планировщик синхронизации** для автоматической генерации файлов по расписанию
5. **SFTP-сервер** как стандартное решение для безопасного файлового обмена

**Технологический выбор:**
- **Java Spring Boot** - совместимость с существующей платформой колл-центра
- **SFTP** - стандартный протокол для безопасной передачи файлов
- **Spring Scheduler** - для управления периодичностью обновлений
- **MS SQL** - использование существующей инфраструктуры банка

### **Альтернативы**

**Альтернатива 1: Прямая интеграция АБС с колл-центром**
- Преимущества: Минимальная задержка обновления ставок
- Недостатки: Прямая нагрузка на АБС, нарушение архитектурного принципа изоляции
- Отклонена из-за рисков для стабильности основной банковской системы

**Альтернатива 2: Единый REST API для всех колл-центров**
- Преимущества: Унифицированный подход, проще поддержка
- Недостатки: Не соответствует ограничениям партнерского колл-центра
- Отклонена из-за технических ограничений партнера

**Альтернатива 3: Ручная отправка файлов по email**
- Преимущества: Быстрая реализация, минимальные технические изменения
- Недостатки: Высокий риск человеческих ошибок, отсутствие автоматизации
- Отклонена из-за операционных рисков и невозможности масштабирования

### **Недостатки, ограничения, риски**

**Недостатки:**
1. Задержка в обновлении ставок у партнера (до 24 часов)
2. Усложнение архитектуры дополнительными компонентами
3. Необходимость поддержки двух различных механизмов интеграции

**Ограничения:**
1. Партнерский колл-центр не поддерживает API-интеграцию
2. Частота обновления файлов ограничена техническими возможностями партнера
3. Отсутствие реального времени в синхронизации с партнером

**Риски:**
1. Риск рассинхронизации ставок между каналами
2. Зависимость от доступности SFTP-сервера
3. Необходимость мониторинга успешности передачи файлов
4. Риск утечки данных при файловом обмене

**Список крупных задач для планирования:**

1. **Сервис депозитов**
   - Реализация REST API для предоставления ставок
   - Разработка генератора файлов в требуемом формате
   - Настройка планировщика синхронизации
   - Реализация механизма кэширования ставок

2. **Внутренний колл-центр**
   - Интеграция с REST API сервиса депозитов
   - Разработка UI компонентов для отображения ставок
   - Обновление базы данных для хранения кэша ставок

3. **Инфраструктура**
   - Развертывание и настройка SFTP-сервера
   - Настройка сетевого доступа для партнерского колл-центра
   - Реализация мониторинга передачи файлов

4. **Партнерский колл-центр**
   - Разработка процедуры автоматического импорта файлов
   - Настройка расписания загрузки файлов
   - Обновление интерфейса оператора для работы со ставками

5. **Безопасность**
   - Настройка шифрования передаваемых файлов
   - Реализация механизма аутентификации для SFTP
   - Аудит доступа к данным ставок
