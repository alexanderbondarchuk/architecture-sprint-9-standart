### **Решение**

**Архитектурный контекст с учетом IT-ландшафта:**

Архитектура строится с учетом существующих систем и их технологических ограничений:

- **Интернет-банк (ASP.NET MVC 4.5/.NET Framework 4.5 + MS SQL)** - монолитная система, требующая минимальных изменений в ядре. Для изоляции нагрузки на АБС предлагается создать отдельный сервис-посредник для работы с депозитами.

- **АБС (Delphi + Oracle + PL-SQL)** - основная банковская система с ограниченным вертикальным масштабированием. Интеграция через PL-SQL процедуры для минимизации рисков.

- **Колл-центр (Java Spring Boot + React.js + PostgreSQL)** - микросервисная архитектура, позволяет расширять функционал силами внутренних Java-специалистов.

- **Сайт (PHP + React.js)** - собственная разработка банка, позволяет быстро реализовать функционал подачи заявок для новых клиентов.

**Ключевые архитектурные решения:**

1. **Сервис депозитов** - новый Java-сервис, развертываемый рядом с системой колл-центра, для:
   - Буферизации запросов к АБС
   - Управления ставками и продуктами
   - Интеграции между системами

2. **Интеграционная схема:**
   - Интернет-банк → Сервис депозитов → АБС (через PL-SQL API)
   - Сайт → Сервис депозитов → CRM колл-центра
   - Все системы → СМС-шлюз телеком-оператора

3. **Управление ставками** - через сервис депозитов с синхронизацией в АБС, что заменяет Excel-процесс и обеспечивает централизованное управление.

### **Альтернативы**

1. **Прямая интеграция Интернет-банка с АБС** - отвергнута из-за рисков перегрузки АБС и зависимости от обновлений подрядчика ИБ
2. **Расширение функционала колл-центра для всех операций** - отвергнута из-за необходимости интеграции с Интернет-банком
3. **Полная автоматизация без участия бэк-офиса** - отвергнута для MVP из-за сложности реализации

**Недостатки, ограничения, риски**

- **Технологическая фрагментация**: интеграция между .NET, Java и Delphi системами требует тщательного проектирования API
- **Зависимость от подрядчиков**: обновление ядра Интернет-банка привязано к подрядчику
- **Ограниченное масштабирование АБС**: вертикальное масштабирование Oracle БД ограничено
- **Безопасность данных**: необходимо обеспечить сквозное шифрование при передаче между разнородными системами
- **Операционные риски**: участие партнерского колл-центра требует четких SLA и протоколов взаимодействия
- **Временное решение**: участие бэк-офиса требует ручной обработки части заявок до полной автоматизации
